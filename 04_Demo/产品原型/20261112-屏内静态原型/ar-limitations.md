## 1. 技术选型说明（计划栈，尚未开工）

下列是可立项的公开路径，不是本轮已落地的工程实现。选型依据为 V3 可行性 / AR 架构收口，以及 CFO 底稿对微信开放文档（摘录访问日 2026-11-07）的归纳。本轮未再次抓取官方文档原文。

1. **主形态**：微信小程序 AR 为主路径；屏内 2D 同玩法为必达降级，不是可删的备选。
2. **官方栈，零第三方 AR SDK**：VisionKit **V1** 泛平面检测 + 点按落位（hitTest）+ 官方 xr-frame 加载 glTF/GLB（或官方 three 路径；**立项时锁一，本轮未锁死渲染栈**）。不引入第三方 AR SDK，以免授权与审核风险进入 Demo。
3. **躲猫猫实现方式**：锚点相对落点的 **2–3 个预设静音偏移** + 淡出 / 半透明意象，而不是对真实家具、窗帘做深度遮挡。点找步数 ≤2，并保留「算了」召唤跳过。
4. **资源形态（工程阶段才需要）**：三维用短 clip 的 glTF/GLB；失败或屏内降级用 WebP/PNG 序列。当前工作区 **未见** 可交付的 GLB，概念 JPG / 展示稿插图 ≠ 三维模型。
5. **权限与审核口径（工程阶段）**：升 AR 时再申请相机；用途声明为互动娱乐，不得写成医疗、助眠或睡眠监测。姓名、房号等 PII 不上传。
6. **换皮与范围**：一套壳、共用状态机；先通单皮、其余同壳换包。换哪一皮由产品架构说明，**不改变**下文「本版不做」项。V3/CFO 定稿写「先通霁霁」；本节点目录说明写架构岗「当前只接影盏」。二者属产品范围对表，不在本文件裁决。

公开路径上，CFO 底稿将「角色真实空间放置」「平面 V1 落位」「点找 + 一次收尾」「glTF/GLB 短 clip」「五 IP 同壳框架（架构）」「零云识别 SDK」标为「已验证可实现（公开路径 / 架构）」。这只表示 **有可跟的官方能力与方案**，不表示本项目已经做成。下列各项仍标「有路径尚未真机验证」，不得写成保证：弱光客房 / 白桌少纹理平面成功率、安卓漂移、全机型兼容、本账号相机审核、WeTest 或等价机型抽测可购性。

## 2. AR 入口技术路径（本节点锁定）

本节点按 CIO 派单与 V3 架构收口，锁定为：

**屏内先通 → 再升 AR → 失败或拒绝则降级回屏内同玩法。**

升 AR 时再问相机，不把相机权限挡在第一次进入之前。用户始终能先走完一局屏内躲猫猫；愿意升 AR、且平面与权限都成功时，再进入真机会话。任一失败都不中断主路径。

### 2.1 推荐主路径

```
进入（选皮或直达本轮单皮）
        │
        ▼
   屏内同玩法先通
   （模拟平面或暖雾底；点按落位 → 预设偏移躲藏 → 点找或「算了」
    → 回位 → 一次可跳过的轻互动 → 结束）
        │
        ├─ 用户选择升 AR
        ▼
   申请相机（AskingCamera）
        │
        ├─ 同意且设备/平面可用 ──► ArSession：点按真实平面落位
        │                              → 同状态机完成躲、找、收尾、结束
        │
        └─ 拒绝 / 超时 / 弱光丢平面一次 / 机型不支持 / 会话失败
                         │
                         ▼
                   立即回屏内同玩法（ErrorDegraded）
                   不另开第二种玩法，不卡在权限页
```

V3 架构收口记载的页面切分：`home → inscreen → ar 分包 → outro`。升 AR 放在独立分包，避免首包过重；失败时回到已通的屏内局，而不是空白错误页。

V3 架构收口记载的十态状态机（原文 Markdown 当前工作区未找到，以下摘自收口摘要，**不是已实现工程证明**）：

`Idle / InScreenPlay / AskingCamera / ArSession / Placing / Hidden / Found / Outro / Ended / ErrorDegraded`

主路径事件顺序与静默沟通架构收口一致：落位 → 躲 → 找到 →（可选）静默沟通 `after_find` → 可随时 `Ended`。`anytime_after_place` **本版不上线**。CFO 的 P0 必达写的是「一次轻互动（先通霁霁关角灯，可跳过）」，**未**把开麦静默沟通列为 P0 必达；本文件不把它写成已经进入本轮必做包。

### 2.2 与 CFO 表述的关系

CFO 底稿产品方案写过「先问开相机或先屏内」。本节点不采用「先问相机」作为默认入口，以免拒相机或尚未准备好环境时卡在权限页。屏内先通、升 AR 再问相机，仍满足 CFO 的验收底线：拒相机也能走完同一套玩法。

结束页禁自动「再来一局」连弹；默认静音，可结束。
