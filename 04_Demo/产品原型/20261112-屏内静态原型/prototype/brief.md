## 2. 页面清单与操作路径

画面编号对齐同目录 `ux-ia-flow.md` §3。本原型只用影盏一皮，没有五选。

| ID | 画面 | 怎么走 |
| --- | --- | --- |
| S0 | 极短启动 | 自动进入主页。启动不问相机。 |
| S1 | 影盏展示主页 | 主 CTA「开始今晚」进屏内；次 CTA「进入空间」才演示询问相机。 |
| S2–S3 | 落位 | 点桌面 / 墙边，影盏坐下（脚不离「地」，不上浮）。躲藏前可「换个位置」**1 次**（本节点 UX 默认，不是历史定规）。点「就在这儿」后不可再改。 |
| S4–S5 | 躲猫猫 | 沿墙暖光做预设偏移并半透明藏起。点找 ≤2 次；「算了，回来吧」可召唤。无倒计时、无排行、无惊吓。 |
| S6 | 找到 / 回位 | 可选「插片确认」（可跳过）。可「开始静默沟通」「先看着」或直接结束。收尾已由用户锁定，界面不再使用待锁定标签。 |
| S7 | 开麦告知 | 使用 UX 建议句。同时写明：本原型不真开麦、不做语音识别。 |
| S8 | 静默沟通（必演示段） | `after_find`。可开麦示意 / 先看着 / 关麦 / 跳过。开麦后用确认、靠近、闲聊、晚安四个意图按钮**模拟**听懂。无 TTS、无咨询式长字幕。约 1–3 次短回应后软收束。 |
| S9 | 收束 | 结束为「关光」+「今晚就到这儿」。收尾已由用户于 2026-11-12 锁定。 |
| S10 | 结束页 | 不自动再来一局。可「回到主页」，也可再选「进入空间」。 |
| S11 | 相机说明 | 仅用户主动「进入空间」后出现（主页次 CTA、局中、结束页均可，不强制先打完一局）。 |
| S12 | 降级提示 | 「这次没能进入空间，我们在屏内继续」。允许或「先在屏内继续」之后，本原型都降级回屏内同玩法。 |

推荐主路径：主页 → 开始今晚 → 落位（可换一次）→ 就在这儿 → 躲藏 → 点找或召唤 →（可选插片确认）→ 静默沟通（可跳过）→ 关光结束。

升 AR：任何时候都不在启动或主页浏览时弹相机。点「进入空间」后先出说明，再示意「允许 / 先在屏内继续」。本原型**不接真机相机**；询问后（含点「允许」）会短暂经过 `ArSession` 示意，随即 `ErrorDegraded`，回到屏内同一套玩法，并写明「不代表已实现 AR」。若在局中升 AR，降级后尽量保留当前进度（已找到就停在找到后；寻找中则回到可继续找或召唤）。

状态机（写在 `assets/app.js`，并在状态标签中可见）：

`Idle / InScreenPlay / AskingCamera / ArSession / Placing / Hidden / Found / SilentComm / Outro / Ended / ErrorDegraded`

其中 `SilentComm` 是产品状态（`after_find`），`InScreenPlay` 与 `ArSession` 是呈现模式。本静态原型里的 `ArSession` 只是一闪而过的说明，不装成真 AR。

## 4. 与 UX / Architecture 文档及 CIO 裁定的对齐

开工核对时，同目录四份文档均已在（后补读并对齐，不是做完再补）：

- `ux-ia-flow.md`
- `ar-entry-path.md`
- `architecture.md`
- `ar-limitations.md`

对齐要点：

1. 页面切分按 `home → inscreen →（可选）AR 询问 / 降级 → outro`；主路径为落位 → 躲 → 找到 → 静默沟通 → 可随时结束。
2. 只接影盏（设计标识 `ipId = yingzhan` 仅作说明，界面不出现五选）。
3. **CIO 裁定（静默沟通）**：本节点静态原型的必演示段。仅 `after_find`，可跳过、可关麦、无 TTS，拒麦不中断躲猫猫闭环。不得写成已实现开麦听懂；不回改 2026-11-07 CFO P0。
4. **用户锁定（影盏一次收尾，2026-11-12，Asia/Shanghai）**：用户在 CIO 窗口选定组合：找到后可选「插片确认」（可跳过），结束时「关光」。本原型已按此实现，不再使用待锁定标签。插片确认可跳过，结束为关光 +「今晚就到这儿」。不把两个收尾动作并列成没有默认路径的开放选项。
5. **CIO 已通过的 UX 默认（落位重放）**：躲藏前可重放 1 次（初落 + 重放共 2 次）。这是**本节点 UX 默认**，brief 与界面都不写成「历史定规」或「V3 原已锁定」。
6. **CIO 已通过的 UX 默认（主页次 CTA）**：主页保留「进入空间」。推荐仍先走屏内，但**不强制**先打完一局才能升 AR。启动（打开原型 / 进入主页）不问相机；升 AR 须用户主动。本原型不接真机相机，询问后降级回屏内同玩法。
7. 真遮挡、人体跟随、复杂暗房 6DoF、台卡必达、疗效 / 助眠、AI 卖点、五皮同开、`anytime_after_place`、TTS：本版不做。
8. 文案红线：可用「娱乐互动 · 夜间陪伴」；结束页若写仪式感，同屏写明不是医疗或心理咨询、无疗效承诺。禁用助眠 / 疗效 / 安神 / 情绪诊断 / 读心 / 保证入睡等。姓名、房号不采集。

与产品路径的已知差异（必须写清）：最终产品在用户允许相机且设备可用后应进入真机 `ArSession`，走同一套玩法。本静态原型按派单与 CIO 补充，询问后一律降级回屏内，并明确「不代表已实现 AR」。这是原型能力边界，不是把产品路径改成「允许相机也不进空间」。

## 5. 影盏收尾、静默沟通等事实

- 影盏一次收尾已由用户于 2026-11-12（Asia/Shanghai）锁定：找到后可选「插片确认」（可跳过），结束为「关光」+「今晚就到这儿」。界面不再使用待锁定标签。
- 「插片确认」表现：坐正约 1 拍，边缘呼吸光与掌心光亮起，头上插片明显提亮并留存暖光（约 2.8 秒，低唤醒）。确认后的静态画面与确认前可区分。确认不交换插片内容；「晚安」仍用插片溶换，二者不混。
- 「关光」用在结束：掌心 / 边缘光渐灭 +「今晚就到这儿」。
- 静默沟通里的「晚安」用插片溶换（内容包示意，不是衣柜换装），这不是结束键。
- 静默沟通全程为模拟：不开真麦、不做语音识别、无 TTS。角色只动不说话。

## 7. 视觉修正说明（2026-11-13，Asia/Shanghai）

针对 CIO 第一次验收通过后的三处视觉反馈，仅改了本目录内样式与脚本（见下）。验收截图另放在 `/workspace/mianyu-demo/20261112-node1/prototype-fix-20261112/`，不进入 `assets/`。

1. **躲藏**：半透明降到约 0.15，并加暗与轻微模糊；优先沿左墙做更大偏移（可接近墙边），同时略缩小、脚仍落在桌面上。文案标明这是意象遮挡，不是真遮挡。点找命中仍跟角色实际位置计算。
2. **面板**：压缩找到后 / 开麦告知 / 静默沟通的文案、间距和按钮高度，面板保持在「今晚就到这儿」之上，让灯笼的头和身体留在可见区，不再只露一个顶。角色不因抬高而出现 Y 轴上浮。
3. **插片确认**：加强坐正、边缘光、掌心光和插片提亮，过程可被看出；确认后暖光留存在角色上。不与「晚安」的插片溶换混用。
