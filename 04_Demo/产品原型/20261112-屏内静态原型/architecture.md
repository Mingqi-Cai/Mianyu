## 1. 页面 / 分包结构

依 V3 小程序 AR MVP 架构收口（[收口页](https://app.notion.com/p/411340bcc39681b186d7ef3d1661acaf)）。完整专册 `miniprogram-ar-architecture-v3.md` 当前工作区未找到，下列切分摘自收口摘要，**细节待源文件找回后补齐**，不是已落地的工程目录。

| 分包 / 页面 | 职责 | 本节点怎么用 |
| --- | --- | --- |
| `home` | 进入、说明低唤醒约定、本轮只呈现影盏（不提供五皮点选首发） | 壳层入口。不在进门前索要相机。 |
| `inscreen` | 屏内 2D 同玩法：点按落位 → 预设躲藏 → 点找或跳过 → 找到后可进入静默沟通 → 可结束 | **必达**。用户必须能先走完一局，不依赖相机。 |
| `ar`（独立分包） | 升 AR 后的真机会话：申请相机、平面落位、同一套状态机 | 工程阶段才接通。升 AR 放独立分包，避免首包过重。本轮静态说明与（若有）静态原型只做入口与失败回退的界面示意，**不接相机**。 |

失败或拒绝相机时，回到已通的 `inscreen` 局（见状态 `ErrorDegraded`），不落到空白错误页，不另开第二种玩法。

渲染栈（官方 xr-frame 或官方 three）由 AR 技术岗在立项时锁一，本文件不提前锁死。零第三方 AR SDK。

## 2. 入口与降级路径

与 `ar-limitations.md` §2 一致，转写如下，便于架构验收对表：

```
进入（本轮直达影盏，不开放五皮点选）
        │
        ▼
   屏内同玩法先通
   （模拟平面或暖雾底；点按落位 → 预设偏移躲藏 → 点找或「算了」
    → 回位 → 找到后可进入静默沟通（可跳过、可关麦）→ 结束）
        │
        ├─ 用户选择升 AR
        ▼
   申请相机（AskingCamera）
        │
        ├─ 同意且设备/平面可用 ──► ArSession：点按真实平面落位
        │                              → 同状态机完成躲、找、静默沟通、结束
        │
        └─ 拒绝 / 超时 / 弱光丢平面一次 / 机型不支持 / 会话失败
                         │
                         ▼
                   立即回屏内同玩法（ErrorDegraded）
                   不另开第二种玩法，不卡在权限页
```

要点：

- 升 AR 时再问相机，不把相机权限挡在第一次进入之前。
- 拒相机也能走完同一套玩法，满足 CFO 验收底线。本节点不采用「先问相机」作为默认入口。
- 弱光丢平面是降级触发条件，不是要在暗房里保证满血跟踪。
- 结束页禁自动连弹；默认静音，可随时结束。

## 3. 状态机与模块边界

### 3.1 十态状态机（收口摘要，源文件未找到）

V3 架构收口记载的十态为：

`Idle / InScreenPlay / AskingCamera / ArSession / Placing / Hidden / Found / Outro / Ended / ErrorDegraded`

主路径事件顺序与静默沟通架构收口、本派单一致：

**Placing（落位）→ Hidden（躲）→ Found（找到）→（可选）静默沟通 `after_find` → 可随时 Ended。**

约束：

- 任一状态下均可进入 `Ended`（可随时结束）。
- 静默沟通默认只在找到（或「算了」召唤回位）之后，即 `after_find`；`anytime_after_place` **本版不上线**。
- 无 TTS；拒麦 / 无麦 / 关麦时，仍走同一状态机，改用屏内或无麦的肢体 / 光效兜底，不中断主路径。
- 躲猫猫：锚点相对落点的预设静音偏移（点找 ≤2，保留「算了」召唤跳过），**不是**真家具遮挡。
- 收口摘要还写过「麦克风权限与 playAction 事件总线」。原 md 不在，本文件 **不编造** 事件名单；只保留「屏内与 AR 共用同一状态机和同一套玩法事件，换皮只换表现包」这一边界。细节待源文件找回后补齐。

### 3.2 模块边界（逻辑模块，不是已实现代码）

| 模块 | 职责 | 明确不做什么 |
| --- | --- | --- |
| 壳层（`home` / `outro` / 本轮单皮入口） | 进入约定、结束、本轮只加载影盏皮 | 不在壳层做五皮点选首发；不提前索要相机；不上传 PII |
| 共用状态机 | 十态流转、可随时 Ended、屏内与 AR 共用 | 不为单个 IP 另起一套流程或「大世界」 |
| 屏内玩法（`inscreen`） | 2D 同玩法必达降级 | 不冒充已接相机的 AR |
| AR 会话（`ar` 分包） | VisionKit V1 点按平面落位 + 官方渲染栈加载短 clip | 不做真遮挡、人体跟随、V2 深度、复杂暗房 6DoF；不引入第三方 AR SDK |
| 换皮包 | 按 `ipId` 加载文案、藏点偏移 JSON、一次收尾、美术 / 短 clip | 当前 Demo 只装载影盏包；接口预留五皮，运行时不同开 |
| 静默沟通层 | 默认 `after_find`，可跳过、可关麦，无 TTS | `anytime_after_place` 不上线；不把展示稿写成已上线听懂能力 |
| 降级与权限 | AskingCamera、ErrorDegraded、回屏内同玩法 | 不卡在权限页；失败不改玩法规则 |

本岗不承担页面开发、测试或验收。静态原型由小程序岗交付，AR 限制由 AR 技术岗维护，交互流程由 UX 岗维护。本文件只定结构与边界，与上述文件对表，不覆盖它们。

## 4. 影盏接入方式（当前 Demo 唯一展示皮）

### 4.1 怎么挂到共用壳

当前 Demo 启动时，壳只装载 `ipId = yingzhan`（影盏）的换皮包，直接进入屏内主路径，不提供其余四皮的点选。另外四皮的包在接口层预留，本节点运行时不加载。

挂接关系（设计，尚未工程化）：

- 共用状态机与页面分包不因换皮而分叉。
- 影盏包提供：落位姿态约束、藏点意象与预设偏移、找到后的一次收尾、静默沟通的招牌差分、文案与美术。
- 屏内与（未来）AR 读同一份包；AR 侧用短 clip 的 glTF/GLB，失败或屏内用 2D 序列。当前工作区 **未见** 可交付的 GLB，概念图 ≠ 三维模型。

### 4.2 已有文档对影盏的形态约束（须遵守，不得写成已做成）

来源：CFO 底稿 §3；展示稿 `/workspace/mianyu-v4/user-attachments/showcase-silent-comm/showcase-silent-comm/index.html`（自述仅供产品沟通，不构成已上线承诺）。

## 6. 明确限制与非目标
